## 1. 目标与范围

**继续只用原有 7 张 HEIC，在现有佛像模型上恢复原照片中已经存在的表面细节，明显减轻色块、模糊、贴图错位和接缝，交付可在 Rebuild3D 中查看、保存、重开和导出的增强版本。**

主体范围沿用第一阶段：中央佛像、手持器物和直接相连的雕塑/岩石底座。天空、树木、寺庙、行人、周边造像和方形台基不作为纹理内容贴到主体上。先沿用已确认的范围，不通过删除难处理部位来制造“变清晰”的效果。

用户此前确认的要求继续有效：照片无法确定的部分允许近似，但必须标出推测来源，保持与原照片可见内容一致。**贴图清晰不意味着几何已经变成实测。**

本阶段的优先级：

1. 解决当前颜色表示和取样分辨率造成的细节损失。
2. 在主体遮罩、可见性和相机对齐可靠的区域使用高分辨率照片。
3. 减轻跨照片接缝、曝光差异及重影。
4. 仅在证据表明纹理无法解决时，局部修整几何。
5. 完成实际应用和导出格式的验收。

首轮不增加照片、不重新启动完整大模型路线，不将生成式超分、凭空补脸、虚构衣纹或增加网格数量作为默认增强方法。用户授权的近似补全仍可用于无观测区域，但需要独立标记，不得用它来证明照片细节恢复成功。

## 2. 为什么现在的贴图粗糙

以下保留计划建立时的原因分析。“待验证”的执行结果见第 10 节及探索记录；并不表示这些检查尚未进行。

| 问题 | 状态与证据 | 对应处理 |
| --- | --- | --- |
| 取色图分辨率过低 | **已确认。** `run_vggt.py` 把 1200×1600 工作图缩为 388×518，再补边到 518×518；`fuse_depth.py` 从这份 `rgb` 为顶点取色，没有利用 4284×5712 的完整正向图细节 | 将几何推理分辨率与纹理取样分辨率分开，纹理回到完整照片 |
| 每个三角面只有一个颜色 | **已确认。** `export_usdz.py` 对三角面的三个顶点颜色取均值；三个角的 UV 都指向同一个 2×2 色块中心。当前 USDZ 有纹理文件，但面内没有照片细节 | 改成具有面积的 UV 三角形，逐像素投影采样真实照片 |
| 视角选择和接缝处理较简单 | **已确认实现限制。** 当前逐顶点选择单个照片颜色，没有连续面片的视图选择、曝光统一及接缝优化 | 以面片为单位选择主视图，先对齐，再在可靠区域处理接缝 |
| 相机或局部表面误差放大 | **待验证影响范围。** 当前相机和深度均为学习估计；在 518 输入上不明显的误差，映射到完整照片后可能出现重影或串色 | 建立高分辨率投影检查，必要时有限修正相机或局部几何 |
| 边缘混入背景、暗部或高光不一致 | **待逐区域验证。** 第一阶段遮罩为粗边界，照片来自不同视角和光照条件 | 检查高分辨率遮罩、遮挡、采样边界与颜色一致性 |
| 网格起伏和法线影响显示 | **待与贴图分离验证。** 当前网格经过体素融合和平滑，细部本身近似 | 对照纯纹理显示、固定灯光和无纹理模型，避免把几何问题全归为贴图 |

代码依据：[输入准备](../scripts/sparse/run_vggt.py)、[融合及取色](../scripts/sparse/fuse_depth.py)、[现有 USDZ 导出](../scripts/sparse/export_usdz.py)。完整照片派生路径见 [原图准备脚本](../scripts/prepare-sparse-inputs.swift)。

据此，最值得先做的是 **“固定网格，使用高分辨率照片重新生成真正的 UV 贴图”**。仅将旧纹理放大到 4K/8K，或继续细分旧网格，不会补回已经丢失的照片细节。这是基于当前实现的工程判断；实际提升幅度以本阶段对照产物为准。

## 4. 分阶段实施与推进条件

### S0：建立可比较的纹理基线

**工作：**

- 固定原图、网格、相机、显示变换和纹理文件摘要；确认普通贴图模式与 Sources 来源模式分别可用。
- 保存 7 个原视角的原图/当前模型对照、固定转台，以及无纹理模型。
- 在原照片细节可辨的部位预先选定 **8 个检查区域**，覆盖头面或冠饰、器物、胸甲、衣褶、底座以及侧面/背面。每个区域保存照片 ID、像素矩形、对应表面、参考细节和主要问题。
- 将“色块/低分辨率”“对齐重影”“背景污染”“接缝/曝光”“几何/法线”分别记录，避免同时更改所有因素。
- 为纹理评估增加明确的图像宽高、相机参数和渲染分辨率。现有渲染脚本使用 `2×主点` 推导画幅，不能直接沿用到高分辨率、裁剪或偏心主点；必须读取真实画幅。

**产物：** `baseline.json`、`review-regions.json`、7 视角对照和 8 处近照。清晰度对照使用至少 1600 长边的渲染及 1:1 局部裁片，不能只看 518 像素缩略图。

**通过条件：** 基线能重复渲染；检查区域和评价口径在增强前固定，不根据增强结果重新挑选有利区域。

### S1：先用小范围证明高分辨率 UV 贴图有效

**工作：**

- 固定第一阶段网格和相机，在一块原图清晰、正面可见的主体区域验证逐像素投影取样，再扩展到完整主体。
- 优先直接从原始 HEIC 解码为新的完整分辨率、方向正确、颜色策略明确的无损纹理工作副本，避免反复 JPEG 编码。已有 `images-full/` 可用于快速对照，但须记录来源与摘要。
- 显式串联原始编码像素、EXIF 正向像素、1600 工作图、518 模型输入、UV 和显示空间变换，核对补边、半像素偏移、上下方向和内参。用已知原图标记点验证往返映射。
- 使用 UV 展开，把三角面的三个角映射成有面积的 UV 三角形；在 atlas 像素上反算表面点，再投影到照片采样。避免每面均色和每顶点颜色成为最终细节上限。
- 先做 2K 验证，再做 4K 候选。4K 是纹理预算起点，不是质量保证；记录 UV 利用率、像素密度、拉伸、岛间留白和有效采样分辨率。
- UV 接缝可以复制顶点，但不得改变三维表面。保留新面到原始面 ID 的映射，延续几何来源分类。

**技术选择：** 使用 [xatlas 官方实现](https://github.com/jpcy/xatlas) 的非官方 Python 绑定 `xatlas==0.0.11`，已在本机运行并冻结发行提交、上游子模块提交、安装二进制摘要及许可，见 `scripts/texture/xatlas-version.json`。UV 接缝增加了顶点；验收比较三维三角面和来源映射，而非只比较顶点总数。

**产物：** 一份保留原网格形状的逐像素贴图候选、2K/4K 纹理、UV 检查图、局部前后对照和投影记录。

**推进条件：** 同一表面区域确实出现旧版没有保留的原照片细节。若出现双轮廓、拉伸或串色，记录后进入 S2；不能靠继续放大纹理或锐化掩盖对齐问题。

### S2：修正高分辨率投影、主体边缘与遮挡

**工作：**

- 在 7 张照片上复查头饰、器物边缘、手臂、衣带、岩石和空隙。高分辨率遮罩须实际检查；输出分辨率高不等于边界精确。
- 每个候选采样位置同时检查：照片范围、主体 mask、表面朝向和网格深度可见性。用网格光栅化深度/Z-buffer 或射线检查遮挡；不把正面的纹理投到背面，也不只依赖低分辨率预测深度判断可见。
- 对轮廓附近设置与取样尺度相符的保守边界，避免插值把天空或树木混入。细杆不能因统一大幅腐蚀 mask 而消失，应单独检查。
- 将学习相机作为初值，检查高分辨率主体特征的重投影。如果存在一致的偏移，优先做带约束的相机微调；无证据时不增加镜头畸变参数或每视图自由形变。
- 相机修正使用独立保留的检查点验收，记录自动匹配、人工点和耗时。拟合点误差下降不能单独证明有效。
- 可尝试以 1600 长边下检查点中位误差不超过 2 像素、P95 不超过 5 像素作为精细混合的初始目标；这是待验证的工程目标，不是已有成绩。不达标区域采用单个可靠主视图或低可信标记，不做强行平均。

**产物：** 修订后的 mask/相机版本、前后投影误差、遮挡检查图、可纹理化区域和缺失区域图。

**通过条件：** 重要部位无新增明显错贴、镜像或背景污染。没有照片支持的部位明确列出；需要修正几何才能解决的问题单独交给 S4，不无限扭曲照片来迁就错误表面。

### S3：完整主体贴图与接缝处理

**工作：**

- 依据清晰度、投影像素密度、视角、遮挡、mask 边界距离和曝光质量，对连续表面区域选择主照片；避免逐顶点频繁切换照片形成花斑。
- 所有 7 张参与可用性评估，但不要求每张在最终纹理中占相同面积。没有可用取色贡献的照片仍保留其几何/轮廓检查角色，并说明原因。
- 在实际重叠且对齐的主体区域估计保守的曝光/白平衡修正；保存参数和未修正版本。避免将原物体的真实色差抹成同一种颜色。
- 优先把接缝放在低差异处，只对对齐可靠的边界作有限融合。细节错位时先修相机/主视图选择，不能将多张照片直接平均成模糊表面。
- 为 UV 岛生成边缘扩展和足够间隔，并检查 mipmap 缩小时是否串色。无照片支持的空洞采用中性或低频填充，独立标为外观推测。
- 普通贴图保留照片色彩；另输出纹理来源/可靠性图。几何推测和纹理是否有照片依据分开记录。

**候选对照：** 以自有可追溯烘焙流程为主；若视图选择与接缝仍是瓶颈，可有限验证 [MVS-Texturing 官方实现](https://github.com/nmoehrle/mvs-texturing)。它要求图像相机与网格已经对齐，不应被当作自动修正错误几何的工具；依赖、许可和本机编译成本另行核验。

**产物：** 完整主体普通纹理、来源纹理、覆盖统计、接缝前后对照及纹理配置。

**通过条件：** 相比 S1，接缝和光照突变有改善，清晰细节没有因混合被明显抹掉。4K 若已受原照片或几何误差限制，不继续无意义地升到 8K；只有实测像素密度不足且资源允许才做 8K 对照。

### S4：按需局部修整几何与显示

此步骤有触发条件：S2/S3 证明局部扭曲、表面起伏、法线或漂浮碎片仍明显破坏贴图。若没有这类问题，记录原因后跳过，不把重新重建全模型当作必经步骤。

- 对照无纹理模型、无额外光照的纹理显示和固定灯光显示，定位问题来源。
- 优先修正法线、明确的孤立噪声及局部网格质量；保留器物、衣带等真实薄结构。
- 必须改变表面时，仅在原图轮廓和对应点约束下做有限调整，逐项保留修改区域与前后模型。重网格或面序改变时重建来源映射，不能把来源丢失的面默认为可信。
- 分别比较“旧几何+新纹理”和“新几何+新纹理”，证明额外几何修改有价值。
- 不直接将照片明暗当成真实凹凸、法线或粗糙度。首版以照片颜色纹理为主，不宣称恢复了去光照反射率或完整 PBR 材质。

**通过条件：** 关键结构和厚度保留，7 视角轮廓无明显退化，清晰度和旋转观感改善。未通过则回退到 S3 最佳候选。

### S5：交付与应用验收

- 生成带实际 UV 贴图的 GLB 和 USDZ；两种格式都须保留面内颜色细节，不能在导出时再转成每面均色。
- 按 [OpenUSD 的 UsdPreviewSurface 规范](https://openusd.org/release/spec_usdpreviewsurface.html) 核对纹理坐标、材质连接及颜色空间；最终仍以 SceneKit/RealityKit 的实际载入和显示为准。
- 普通查看默认展示主体贴图，Sources 保留几何推测查看；纹理来源图作为独立附件，至少能清楚查看“照片支持”和“外观填充”区域。
- 延续现有 `.rebuild3d-result` 包的照片身份和附件摘要校验。优先通过新增受校验附件承载纹理来源；确需修改格式语义时再版本化并测试兼容性，不为了第二阶段编号直接升级项目格式。
- 在项目副本中通过 Load Approximation 接入增强结果，完成旋转、放大、来源切换、保存、退出重开和导出；验证原图和旧结果保留。
- USDZ 纹理内嵌；GLB 资源完整；导出后移动到新目录仍能打开，不依赖实验目录的绝对路径。附来源包一同交付。
- 在全新输出目录重复运行增强流程，记录参数、输入摘要、纹理及报告。确定性步骤应复现摘要；不能保证逐字节一致的步骤须记录差异及视觉/数值容差。

**通过条件：** 满足下一节全部必验项，才将本阶段标为完成。研究图变清晰但最终应用仍粗糙、丢贴图或无法重开，不算完成。

## 5. 如何证明增强有效

以下保留执行前固定的验收口径；实测结果与证据见第 10 节，不因实验结果降低标准。

| 验收项 | 完成标准 |
| --- | --- |
| 真实细节恢复 | S0 固定的 8 个区域至少 6 个能辨认更多原照片中存在的细节，其余无明显退化；逐区域保存原图/旧版/新版及判定理由。若原图本身不清晰，S0 就标出，不能增强后临时更换区域 |
| UV 与取样有效 | 纹理来自完整分辨率照片，UV 面有面积，面内含真实变化；保留像素到表面和源图的对应关系。单纯放大文件尺寸不通过 |
| 7 图一致性 | 同一增强模型输出全部 7 个对应视角及固定转台；无新增明显双轮廓、器物错位、跨面串色、天空/树木污染或凭空出现的纹理 |
| 公平比较 | A/B 使用同样画幅、显示大小、灯光和曝光策略。若相机修订，旧/新模型都在同一评估相机集重渲染，并保留旧相机下的历史基线，不能只给新版更有利的视角 |
| 几何保护 | 纹理阶段三维表面不变，允许 UV 接缝复制顶点；可按原面 ID 对应核对坐标。若 S4 改几何，同一评估设置下每视角轮廓 IoU 比基线下降不超过 0.01，且关键器物/肢体关系人工检查通过 |
| 来源完整 | 所有有效纹理区域都有照片及处理记录，外观填充和低可信区域可见；几何学习/补全分类不因重新贴图被删除或升级为实测 |
| 实际应用 | 新版普通贴图、Sources、放大旋转、保存、退出重开、导出及离开工作目录后打开均通过；不把脚本渲染当作全部 UI 验收 |
| 可重复及保护 | 固定 7 图摘要不变；旧项目可用；新目录可复现主要增强结果；保存或导出失败不会替换旧结果 |

额外记录：照片支持/低可信/填充覆盖率、接缝两侧颜色差、UV 利用率、纹理数量/尺寸、文件大小、处理时间和内存。覆盖率须同时说明按 UV 像素还是按表面积计算；不得只报一个无法比较的百分比。

可计算同一有效主体区域的 SSIM/颜色误差等辅助指标，但不得仅靠锐化分数、纹理文件大小、训练视角拟合分数或单张正面效果图宣布成功。照片参与了贴图生成，因此原视角匹配是输入一致性，不是独立真实性验证。若做留一视图检查，只在其他视图确有覆盖的区域评价，并明确它仍不等于完全独立的几何验证。

## 6. 几何与纹理来源分别记录

| 层面 | 必须保存的内容 |
| --- | --- |
| 几何 | 第一阶段学习深度/轮廓补全分类；原面 ID；局部修整操作及受影响区域 |
| 照片取色 | 原照片 ID/摘要、投影像素或可重算映射、所用相机和 mask 版本、曝光修正 |
| 多图融合 | 主照片及其他参与照片、权重或可复现规则、可见性和一致性检查 |
| 低可信与填充 | 不可观测、遮挡、斜视、模糊或边缘风险的原因；外观填充方法与作用区域 |

为 atlas 输出照片索引/权重及有效性图，至少能反查检查区域的主要来源。压缩或重排 UV 时保留原面映射。**“纹理来自真实照片”与“贴在正确三维位置”是两个判断，不能混为一谈。**

## 7. 实验组织与资源

执行前建议的目录结构如下；实际产物采用同一根目录，具体路径见探索记录。普通贴图及来源图直接置于候选目录，不使用下例中的两个贴图子目录。

```text
build/seven-photo-statue-stage2/
  baseline/                   # 摘要、固定视角、8 处细节和显示设置
  inputs/                     # 新纹理工作图、mask、颜色与像素变换
  experiments/<run-id>/
    config.json
    cameras.json
    model.glb
    model.usdz
    textures/
    geometry-face-map.npz
    texture-provenance.json
    texture-source-maps/
    review/                   # 7 视角、8 局部、转台和来源图
    report.json
  best.json                   # 当前最佳候选路径及摘要，不覆盖实验
  delivery/                   # 完整项目、USDZ、来源包及复现说明
```

- 继续在现有 Apple Silicon / 16 GiB 机器上本地处理；照片不上传。优先逐图、分块或分 UV 岛烘焙，不同时展开所有照片与高倍浮点 atlas。
- 先 2K、再 4K，8K 有条件进入。单张 4K RGBA8 纹理基础像素约 64 MiB，8K 约 256 MiB；实际内存还包含 mipmap、浮点工作缓冲、深度和多份贴图，不能只按压缩文件大小估计。
- 每轮记录时间、进程 RSS 和适用时的 MPS 内存；统一内存数字不简单相加。初始单实验预算 20 分钟、单项内存 11 GiB，达到边界保留日志并缩小规模；预算调整须说明依据，不视为成功保证。
- UV、投影、接缝和几何分别做有限对照；每次只改变可解释的因素。同一路线无新证据时不无限调阈值。
- 新依赖固定版本并核验许可；第一阶段研究权重的许可边界继续有效。纹理增强成功不等于可以把研究权重随应用商业分发。
- 人工 mask、对应点和审核分别记录耗时，不混入自动处理性能。仅在修改相关实现后运行针对性测试和构建，不为文档变更重跑重建。

## 8. 风险、降级及完成边界

| 实际情况 | 处理方式 |
| --- | --- |
| 原图某处模糊、过曝或遮挡 | 使用较清晰的其他真实视角；都无信息时保持低可信/近似，不生成“看似真实”的新细节冒充恢复 |
| 贴图清晰后暴露相机或几何错误 | 按 S2/S4 定位，保留纹理与几何的独立对照；不退回模糊贴图来掩盖问题 |
| 跨照片融合产生重影 | 回到可靠主视图，缩小融合范围；保留清晰区域，再解决错位 |
| 完整 UV 展开或烘焙资源超限 | 分区域、分 atlas 或降低工作分辨率；保留能解释来源的最佳候选，不强推 8K |
| GLB 清晰而 USDZ/应用模糊或缺图 | 检查 UV、纹理打包、颜色空间、过滤与材质；以实际交付格式修复后的表现验收 |
| 达不到预定细节提升 | 如实标为部分进展并记录瓶颈，保留最佳版本，不降低标准后宣布第二阶段完成 |

本阶段完成的是**这组固定七图、同一主目标的纹理增强及应用交付**。不同时承诺完整 P1 照片视角产品界面、任意少量照片的一键高精重建、真实尺寸测量或完整 PBR 材质恢复。
