## 本版变更

v1 已提出使用 iPhone 系统相机拍照，但没有充分规定普通照片与研究数据的关系。本版将以下内容落实到输入要求、界面、开发步骤和验收中：

- 首版必须接收 iPhone 系统相机提供的 HEIC、JPEG 照片，不要求用户准备深度、轨迹、相机标定或研究数据目录。
- 用户只需“添加照片 → 开始重建 → 查看彩色模型”，格式处理、参数读取和项目内部文件由应用负责。
- 保留原图与已有元数据；将工作副本与原图分开，维持照片和估计视角之间的对应。
- 明确 ProRAW / DNG 属于后续兼容范围，不能把“支持 iPhone 照片”写成首版支持所有拍摄格式。
- 首版必须通过“iPhone 16 Pro 系统相机照片原样导入”的实际验收，研究数据只能作为补充。
- 保留已有工程与验证成果，在其上增量开发；将 HEIC 基线、数据迁移、导入、界面、P0 实拍、P1、稳定性与交付拆为七个阶段。
- 首次添加照片时自动建立可恢复草稿，保存时再选择正式项目位置；新建项目和选择质量不再是添加照片的前置步骤。

## 1. 项目主旨

Rebuild3D 是一个面向个人使用、可继续扩展的本地三维重建应用。用户打开应用后，导入同一物体的多角度照片，启动重建，得到可以旋转查看、保存和导出的带颜色贴图的三维模型。

**三维重建是项目的基础目标。** 产品名称、首页、开发顺序和验收标准都应围绕这一目标展开。

**普通照片就是主要输入。** 用户不需要理解相机矩阵、深度图、置信度、关键帧和点云，也不需要安装专门的扫描应用才能开始。应用承担数据整理与重建处理，用户主要负责拍摄同一物体的多角度照片。

首版核心使用情景：用户用 iPhone 16 Pro 系统相机拍一组照片，传到 Mac 后原样拖入 Rebuild3D，点击重建，查看并保存带颜色贴图的模型。

恢复原始照片的拍摄视角是重建完成后的查看与检查功能：用户选择某张照片，三维视窗切换到估计的对应机位，并允许对照原图查看模型。它不应取代三维重建成为产品的主要定位。

GitHub 项目简介：

> A native macOS app for reconstructing textured 3D models from photographs.

## 2. 使用条件与初始范围

### 2.1 现有设备

- 开发与重建设备：MacBook Air M5，16GB 统一内存。
- 拍摄设备：iPhone 16 Pro。
- 首版采用本地处理，照片无需上传服务器。
- 首版可以使用 iPhone 系统相机拍照，再将照片传入 Mac；不依赖先开发一个 iPhone 应用。
- 用户无需将 iPhone 设置为“最兼容”，也无需开启 ProRAW 或使用 LiDAR 扫描应用。
- 支持通过 AirDrop、USB 或其他方式已经传到 Mac 的照片文件。传输方式可能保留 HEIC，也可能转成 JPEG，两者都必须可用。
- 系统照片图库直接选择、手机向桌面自动传输等能力后续单独评估；首版不依赖这些集成。

### 2.2 首先支持的对象

优先支持静止、刚性、表面有可识别纹理的日常物体，例如鞋子、石雕、木制品和摆件。

“通用重建”表示不绑定人脸这一种对象。首版仍应从单个物体开始验证，不承诺所有材质、尺寸和场景都能成功重建。

玻璃、镜面金属、纯色光滑表面、细线结构和会移动或变形的对象属于困难场景。真人脸部、完整头部、房间和大场景可作为后续方向单独评估。

### 2.3 对三维结果的定义

合格结果至少包含：

1. 三角网格：表达物体表面形状。
2. UV 坐标及颜色贴图：将照片中的表面颜色映射到网格。
3. 可用材质：让模型在支持的查看器中正常显示颜色。

仅得到灰色网格、彩色点云或高斯泼溅数据，不满足本项目首版的完整输出要求。

首版主要输出格式为 **USDZ**。GLB、OBJ 等格式转换作为后续扩展，必须验证转换后贴图和材质仍然正确。只导出几何、不保留颜色的结果不能算转换成功。

### 2.4 输入照片的产品约定

“原始照片”指用户拿到的原照片文件，不等同于摄影术语中的 RAW。iPhone 的 HEIC 本身就是正常输入；Apple ProRAW 使用的 DNG 是另一类格式。

| 输入 | 首版约定 | 用户体验 |
| --- | --- | --- |
| iPhone HEIC / HEIF | P0 必须支持常见 iPhone `.heic` 照片；其他 HEIF 文件按实际解码能力判断 | 原样导入，不要求用户手动转图 |
| JPEG / JPG | P0 必须支持 | 与 HEIC 使用同一导入流程 |
| PNG | 可作为普通静态图片兼容项，在发布前验证 | 不把截图等同于高质量拍摄素材 |
| Apple ProRAW / DNG | P2，首版不承诺 | 未支持时明确指出受影响文件，并继续允许处理其他受支持照片 |
| Live Photo 导出的静态照片及伴随视频 | P0 使用受支持的静态照片；忽略伴随视频 | 不把 MOV 当作照片，也不把一张实况照片重复计数 |
| 深度、相机参数、轨迹等辅助文件 | 非必需输入；首版不要求解析外部研究格式 | 导入照片时不因缺少这些文件而报错 |

首版不提供任意视频抽帧重建，也不宣称直接支持所有相册资产类型。将来支持 DNG 时，由应用在后台完成解码与必要的工作副本生成，保留原文件，统一处理颜色和元数据，不要求用户使用第三方转换工具。

### 2.5 研究数据目录与普通照片的关系

TMO 等数据集使用专门采集程序，把照片、传感器记录和处理结果分开保存。这是数据集的组织方式，不是 iPhone 系统相机的标准输出，也不是 Rebuild3D 的输入门槛。

| 数据集目录 | 内容与作用 | Rebuild3D 的处理原则 |
| --- | --- | --- |
| `rgb/` | 原始彩色照片 | 作为主要重建输入 |
| `rgb_keyframe/` | 筛选出的照片 | 可作为另一组输入，不与 `rgb/` 自动混合导入 |
| `cameraParam/` | 相机参数或标定数据 | 可用于开发对照，不要求用户提供 |
| `depth/`、`confidence/` | 深度及可信程度 | 可选增强信息，普通照片缺失时仍允许重建 |
| `gravity/`、`trajectory/` | 重力与相机运动估计 | 可选采集信息，不要求系统相机照片具备 |
| `rgbdsfm/sfm_final` | 从图像计算出的结构与相机结果 | 属于研究处理结果，不是运行重建的前置材料 |
| `filtered_*`、`preprocessed/` | 过滤、整理后的研究数据 | 不进入普通用户的主流程 |

对于 PIX4D 的示例工程，照片目录、点云和 OPF 工程也应分别理解。测试重建输入时只需图片目录，不要求用户同时导入已经生成的点云和工程文件。

普通照片没有完整相机轨迹，不能仅靠读取 EXIF 获得所有机位。应用应通过重建过程估计相机与几何；读取到的元数据只是可用辅助信息。缺少深度不阻止基础重建，但真实尺寸可能需要后续尺度约束。

## 3. 技术路线与上游项目

基于以下项目进行二次开发：

- 上游仓库：[ekarad1um/Photogrammetry](https://github.com/ekarad1um/Photogrammetry)
- 本次检查版本：`43c66741e3f912ddd29292858d6f6bc01441606e`
- 应用框架：Swift、SwiftUI、RealityKit。
- 重建引擎：Apple Object Capture / `PhotogrammetrySession`。
- 上游许可证：MIT；沿用代码时保留原有版权与许可声明。

上游应用代码开源，Apple 的底层重建引擎属于系统框架，并非本项目能够修改的开源算法。首版接受这一依赖，以完成苹果设备上的实际重建功能为优先。

上游规模较小，本次检查约为 16 个 Swift 文件、906 行代码，已有图片文件夹导入、参数设置、重建进度、简单模型预览和 USDZ 导出。可以复用这些基础，同时逐步拆分业务逻辑和界面。

建议新项目面向 **macOS 26 或更新版本**。理由是原始照片视角对齐需要的估计相机内参和镜头畸变接口从 macOS 26 起提供。基础相机位姿接口从 macOS 14 起可用；应用运行时仍须检查硬件与 API 支持情况。

当前已核实本机 macOS、Swift 与 SDK 环境，并通过命令行编译和真实重建建立上游服务基线。后续复用现有 Swift Package 工程、重建服务、项目存储和查看器；环境变化时重新核实兼容性。完整 Xcode 工程及原始上游 GUI 的未验证项继续记录，具体进度见第 15 节。

## 4. 目标使用流程

1. 打开 Rebuild3D，直接添加照片；也可打开已有项目或恢复未保存草稿。
2. 拖入 HEIC / JPEG 照片、选择多张照片，或导入包含照片的文件夹。首次添加时应用自动建立草稿，无需先选择保存位置。
3. 应用自动读取照片并将原图与导入清单写入当前项目或草稿，显示缩略图、数量和需要处理的问题；用户可移除不需要的照片。
4. 直接点击“开始重建”，使用应用推荐设置；有需要时再展开质量选项。
5. 查看进度；必要时取消，失败时看到可理解的原因。
6. 重建完成后，在主视窗中查看带颜色贴图的三维模型。
7. 自由旋转、缩放和移动视图，检查模型各个角度。
8. 在后续视角功能中，点击原始照片，将三维相机切换到对应估计机位，并对照原图。
9. 首次正式保存草稿时选择 `.rebuild3d` 的名称和位置，已有正式项目直接保存更新；关闭应用后再次打开，直接恢复模型和已有结果。尚未正式保存的草稿也应可在重启后恢复。
10. 根据需要导出 USDZ 模型。

保存项目与导出模型是不同操作：保存项目保留后续查看所需的照片、参数和相机信息；导出模型生成交给其他软件使用的三维资产。

“新建”和“打开”仍保留在工具栏。新建进入空白草稿流程；草稿的落盘、恢复、正式保存及丢弃约定见第 8.1 节。

整个流程中不要求用户创建特定目录、输入焦距、提供相机轨迹、生成深度图或选择算法模块。只有照片不足、读取失败、存储不足等影响操作的问题需要提示；详细技术记录进入可展开的诊断信息。

## 5. 功能优先级

### P0：基础三维重建闭环

- 新建、保存和打开本地项目。
- 首次添加照片自动建立可恢复草稿；保存时再选择正式位置，保存失败不丢失草稿资料。
- 导入图片文件夹及多张 HEIC / JPEG 照片，展示方向正确的缩略图；不用手动转换格式。
- 没有深度、轨迹、标定文件时，仍能仅凭照片启动重建。
- 保留原始文件和已有元数据，建立稳定照片 ID；必要转换只发生在工作副本中。
- 对明显无效、无法读取或不支持的输入给出逐张提示；混合选择时允许用户继续使用有效照片。
- 忽略输入文件夹中的普通辅助文件、伴随视频和系统隐藏文件，并用简短摘要说明已忽略的内容。
- 默认提供合适的重建设置，让用户不必理解引擎参数即可开始。
- 调用 Object Capture 生成带颜色贴图的模型。
- 显示重建进度，支持取消与失败后重试。
- 在应用中查看模型，支持自由旋转、缩放、平移及重置视图。
- 导出包含贴图的 USDZ。
- 关闭并重新打开项目后，可以直接查看已完成模型。

### P1：原始照片视角与对比

- 获取并保存参与重建照片的估计相机位置和朝向。
- 建立照片、样本 ID 和相机参数之间的稳定映射。
- 点击照片切换三维相机，恢复对应的观察方向与尽可能一致的构图。
- 显示原图与三维渲染的并排对比。
- 标明“已定位”“未定位”“近似视角”等状态。
- 支持切回自由观察模式；保存并重开项目后，照片视角仍然可用。

P1 对普通 HEIC / JPEG 照片同样成立：相机位姿来自重建计算，不要求用户提前提供 `trajectory/`、`cameraParam/` 或其他参数文件。

P1 应尽早在已有独立探针上做小范围坐标与投影验证；完整照片视角及对比界面在 P0 验收后接入。第一批工作优先解决 HEIC 路径和数据持久化。

### P2：后续增强

- 原图与渲染画面的半透明叠加、分割线对比。
- 在三维空间显示拍摄机位或视锥。
- GLB、OBJ 等模型格式转换。
- 更完整的质量诊断、批量重建与性能优化。
- Apple ProRAW / DNG 的后台解码、颜色处理与原图关联；完成验证后再对外宣称支持。
- 系统照片图库选择与更方便的 iPhone 到 Mac 传输。
- iPhone 引导扫描端及深度信息采集。
- 对人脸、室内空间等特定对象建立单独的采集与重建策略。

后续 iPhone 采集端通过引导拍摄自动记录可用的深度、运动等信息，并随项目传递。它是提高采集便利性和数据质量的可选入口；普通照片导入仍需长期保留。

## 6. 界面方案

沿用已有可调整大小的 macOS 主窗口，继续优化照片入口、默认设置和任务状态。

| 区域 | 内容 |
| --- | --- |
| 顶部工具栏 | 新建、打开、导入照片、开始重建、取消、保存、导出 |
| 左侧照片栏 | 缩略图、照片名称、选择状态；P1 增加定位状态 |
| 中间主视窗 | 带贴图的三维模型；未重建时显示简明引导；重建时显示进度 |
| 可展开的右侧面板 | 原图、简化的质量选项、可执行的问题说明；P1 增加视角对比 |
| 底部状态栏 | 项目状态、照片数量、重建进度与必要提示 |

交互约定：

- 空状态只突出“添加照片”，配一句“从不同角度拍摄同一物体”。拍摄帮助可展开查看。
- 首次拖放与“添加照片”采用同一草稿流程，不先弹出项目保存对话框；可恢复草稿应有清晰入口。
- “开始重建”应是导入照片后的主要操作。
- 不满足启动条件时明确解释原因：照片不足、本机不支持或超出引擎数量/尺寸限制；超大照片逐张标记，用户移出输入清单后可继续，项目原图保留。最低启动数量不代表物体覆盖充分。
- 质量选择不是必填步骤。默认使用经本机验证的推荐设置；`featureSensitivity`、矩阵、点云和深度置信度等技术项不进入主界面。
- 重建进度使用真实可获得的状态，例如“正在准备照片”“正在重建”“正在保存模型”。没有可靠进度值时显示正在处理，不制造精确百分比。
- 点击照片后，高亮当前照片；有位姿时进入照片视角，没有位姿时显示原因并保留原图查看。
- “照片视角”保持原照片画幅；窗口大小变化时使用留边等方式，避免改变构图。
- 自由拖动三维视图后进入“自由观察”，用户可点击“返回照片视角”。
- 重建错误应说明发生了什么、哪些输入受影响、是否可以重试，避免只显示内部错误码。

问题提示示例：

| 实际情况 | 用户看到的提示 |
| --- | --- |
| 个别文件无法解码 | “2 张照片无法读取，可以移除后继续。”并显示文件名与占位行；不要求生成无法读取的缩略图 |
| 混入暂不支持的 DNG | “这些 ProRAW 照片暂不支持，其他照片可以继续导入。” |
| 文件夹含辅助文件 | “已添加 59 张照片，其他文件已忽略。” |
| 已确认部分照片被引擎跳过 | “部分照片未参与重建。”有可靠映射时标出照片；暂时无法关联时保留批次提示与诊断，不猜测文件或原因 |
| 仅位姿请求失败，模型可用 | “模型已生成，暂时无法切换到照片视角。” |

如果模糊检测、覆盖度分析尚未实现，不能伪装成已完成的检查，也不能根据通用失败码直接断言“照片太模糊”或“背面缺拍”。这些提示必须有可解释的检测依据。

### 6.1 给用户的简明拍摄指引

1. 先选择一个静止、表面有纹理的物体，放在光线均匀的位置。
2. 用系统相机普通照片模式拍摄，尽量保持同一镜头和缩放倍率，让整个物体留在画面内。
3. 围绕物体拍一圈，再改变高度补拍；相邻照片要看到大部分相同区域。
4. 把照片传到 Mac，直接添加到 Rebuild3D。

详细帮助可解释相邻照片尽量有约 70% 或更多重叠、保持清晰和曝光稳定等要求。不要把固定张数当作成功保证，也不要让用户把调整格式、准备传感器数据当成拍摄步骤。

## 7. 重建与视角恢复的实现要点

### 7.0 照片导入与准备

完善现有独立照片导入层，负责将普通照片变成引擎可用的输入。界面展示用户认识的照片，内部管理准备流程。

1. **识别输入**：根据文件类型与实际解码结果判断是否为可用静态图片，不能只依赖扩展名。HEIF 应按主图规则读取，不能未经判断就拒绝所有多图容器或固定取索引 0；元数据、缩略图和预览使用一致规则，并核对引擎实际使用的图像。首版针对所选文件或文件夹中的照片导入；不盲目递归合并整个研究工程，避免同时混入原图和关键帧副本。
2. **分配稳定 ID**：每张导入照片有独立 ID，保留来源名称与项目内路径。来自不同目录的同名文件不能互相覆盖；使用原文件内容摘要辅助精确去重，重复添加在跨批次、重开项目后也应明确提示或跳过。P0 不做视觉近似去重。
3. **读取可用元数据**：记录实际类型、主图索引、像素尺寸、显示方向以及可以读取的拍摄和颜色信息。不把缺少 EXIF、深度或轨迹当成输入无效；未知信息明确留空。
4. **保留原图**：原文件复制到项目内，不覆盖、不重新编码，不主动丢弃其中的颜色配置与辅助信息。
5. **按需准备工作副本**：引擎能够直接读取时优先使用原图；确需转换、缩放或方向归一化时，使用独立副本并记录变换。特别注意 HEIC 中可能存在的深度等附加数据，不能无条件转成 JPEG 后宣称全部信息仍被保留。
6. **统一颜色处理**：正确解码颜色配置，为重建输入和预览采用一致的处理规则，避免把宽色域或 HDR 的显示差异误认为贴图损坏。P0 先验证受颜色管理的 SDR 预览与模型对照，保留原图完整信息；确需生成 SDR 工作副本时记录颜色转换或色调映射。高动态范围输入的处理效果需实测，完整 HDR 材质与显示链路不作为首版前置条件。
7. **维护坐标对应**：保存原图与工作副本的尺寸、方向、缩放及裁剪关系，记录处理版本和文件摘要；区分编码像素、显示方向与实际重建输入的坐标。引擎内部降采样单独记录，不能未经验证就认定返回内参对应原图分辨率。
8. **报告导入结果**：分别统计已导入、重复、不支持的照片、无法读取及已忽略的文件。局部问题不直接终止整个批次，但有效照片无法满足引擎要求时应阻止启动并说明原因；最低输入张数不代表重建质量保证。

保存的数据应足以解释某张原图如何成为某个重建样本。不要仅依赖缓存文件名或导入顺序建立关联。

HEIC 的“可解码”“可作为引擎输入”和“可生成合格模型”分别验收。先验证原图直入，仅在真实兼容性、方向或资源测试显示需要时实现相应工作副本处理。

### 7.1 重建服务

沿用现有独立重建服务，继续完善输入、配置、进度、取消、输出和错误管理。界面只观察状态和发出操作，不直接承担全部重建流程。

第一版沿用 `PhotogrammetrySession` 的模型输出。接入 P1 时，在同一会话中请求模型和 `.poses`，分别记录每一类请求的完成、失败和进度。

**不能在第一个请求完成时就退出结果监听。** 固定上游版本存在这一行为；当前 Rebuild3D 已持续监听至会话结束，接入 `.poses` 时应保留此行为并分别管理各请求结果。模型已成功、位姿失败时，应保留可用模型并单独提示视角功能不可用，不能把旧模型的相机数据绑定到新模型。

### 7.2 照片与相机的对应

- `posesBySample` 提供样本 ID 到估计相机位姿的映射。
- 使用图片文件夹创建会话时，可利用 `urlsBySample` 对应原始图片。
- 若会话输入的是工作副本目录，先通过 `urlsBySample` 找到工作副本，再由导入清单映射回原图 ID；不能把副本路径直接当作原图身份。
- 使用自定义样本序列时，由应用维护样本 ID 到图片的映射。
- 不根据文件夹枚举顺序或文件名排序猜测位姿对应关系。
- 被跳过、无效或未成功定位的照片要保留明确状态，不能伪造视角。

基线阶段需验证无效或跳过样本能否通过可靠映射关联到原图；必要时评估自定义样本 ID 输入，并验证原有元数据的利用情况。不能用文件排序补造关联，也不能把缺少位姿一律解释为照片未参与重建。

### 7.3 恢复观察方向与构图

视角恢复需要同时处理：

1. 相机位置与朝向。
2. 相机内参，包括焦距与主点。
3. 图片尺寸、方向信息、裁剪和显示宽高比。
4. 可用的镜头畸变信息。
5. 重建模型、导出模型和查看器之间的坐标变换。

Apple 的内参和畸变数据可能为空。存在这些参数时按参数构建投影与对比流程；缺失时可用可验证的近似方案，但必须在界面和保存数据中标记。仅设置相机位置和朝向不足以承诺与原照片构图一致。

原图叠加时，原图和渲染画面应处于同一种投影条件下。例如使用已校正的原图对比针孔相机渲染，避免把镜头畸变误认为重建几何误差。

### 7.4 坐标处理

固定上游版本的预览会将模型平移到中心，使用固定 80° 视场角，再自动环绕展示。后续照片视角应按以下坐标约定接入，不能直接沿用上游固定构图。

保持重建模型与相机参数的坐标关系。若为方便显示而对模型施加平移、旋转或缩放，相机和其他辅助对象必须应用一致的坐标变换。

开发中明确记录矩阵方向、坐标轴约定、单位和矩阵存储顺序，避免相机朝反方向、模型镜像或投影比例错误。不要在没有验证的情况下直接把外参矩阵赋给查看器相机。

### 7.5 效果边界

恢复的是算法估计的机位，不能保证所有输入照片都有位姿，也不能保证渲染结果和原图逐像素相同。

原图包含背景、现场光照、反光和遮挡；重建模型存在缺失、平滑和纹理融合。这些因素都会产生差异。没有深度或已知尺度约束时，也不能将重建结果直接作为准确的尺寸测量工具。

## 8. 项目文件与持久化

不能只保存一个模型文件，也不能将唯一结果留在临时目录。

沿用已注册的 `.rebuild3d` 自包含 macOS 文档包，让用户在 Finder 中看到一个可打开的项目文件。P0 在 `project.json` 中维护当前照片身份和导入属性；每次运行另存不可变输入快照，避免两份可编辑导入清单相互矛盾。以下为后续扩展结构，无需用户创建或维护这些目录：

```text
Example.rebuild3d/
  project.json       # 格式版本、当前照片与导入属性、设置、已提交结果引用和状态
  images/            # 原始输入照片，保留可用元数据
  thumbnails/        # 照片列表缩略图，可重新生成
  runs/<run-id>/
    inputs.json      # 本次重建的照片 ID、工作版本、转换及样本对应记录
    cameras.json     # P1：同一次重建的位姿、内参、定位状态及照片映射
  models/
    <model-id>.usdz   # 包含材质和贴图的不可变重建结果
  logs/              # 任务日志与失败原因
  cache/             # 可重新生成的缩略资料、工作副本及其他中间数据
```

保存约定：

- 原图默认复制到项目内，避免外部照片移动或删除后项目失效。
- 项目内使用相对路径，允许整个项目目录移动。
- 元数据包含格式版本，独立于需求文档的 v2 编号。旧格式项目迁移时保留照片 ID、原图与可用模型；缺失属性从原图补读或标记未知，不伪造旧相机信息，不要求用户重新重建。
- 重开项目显示用户原来的照片与名称；后台转换不改变用户对照片的识别。
- 如保存的相机参数基于工作副本坐标，需持久保存必要的转换记录；清理缓存不能破坏已完成模型和照片视角的恢复。
- 相机记录包含样本 ID、照片 ID、工作版本、照片路径、位姿、可用内参、图片尺寸与方向、定位状态，以及使用的坐标约定；相机与模型绑定同一运行版本。
- 先写入并校验不可变模型与运行资料，再原子切换 `project.json` 的结果引用。多个 JSON 分别原子写入不等于整个项目的事务；迁移或提交失败时保留原项目可用。界面显示是否还有未保存内容。
- 已有可用模型在新一轮重建失败时仍应保留。
- 区分可删除缓存和不可丢失的项目资料。
- 保存并重开项目不要求重新重建；中断后的重建断点续算属于另一个功能，首版不承诺。

固定上游版本会在离开预览页面时删除临时模型。当前 Rebuild3D 已由项目管理层持久保存模型；后续草稿和多请求改造必须继续保持这一行为。

### 8.1 可恢复草稿的生命周期

1. 首次添加照片时，在 Application Support 的受管理目录建立草稿项目；不把唯一原图或结果放在临时目录。
2. 导入原图、清单和已完成结果及时落盘；重新启动后能够恢复已成功保存到草稿的资料。草稿恢复不等于重建任务断点续算。
3. 用户执行保存时选择正式名称与位置。复制或迁移完成并校验新项目可打开后，才切换项目引用、清理原草稿。
4. 保存取消、目标不可写、磁盘空间不足或迁移中断时保留原草稿；未完成保存不能显示为已正式保存。
5. 除成功转为正式项目后的清理外，用户明确丢弃时才删除草稿；关闭窗口或退出应用不直接清除可恢复资料。

## 9. 16GB 内存下的资源策略

- 一次只运行一个重建任务。
- 默认设置先从 `reduced` 验证，再依据实际结果调整。将 `medium` 及更高质量放在可展开选项中，不要求用户理解这些引擎档位名称。
- 照片列表使用缩略图，原图按需读取。
- 避免同时将全部原图、所有纹理和重复模型常驻内存。
- 输入处理、重建和保存避免阻塞主界面。
- 缩放或转换照片时保留原图，正确更新与像素尺寸相关的相机参数。
- 记录任务耗时、内存峰值、输出大小和失败原因，再决定是否增加更高质量档位。注明内存测量口径，区分应用进程采样、系统压力与可观察的辅助进程，不把应用 RSS 当作系统总峰值。

先核实已记录的 59 张 HEIC 和 33 张 JPG 的本地目录与文件，再建立基线，并尽早使用 iPhone 16 Pro 自拍照片验证实际入口。对于较大批次或更高分辨率输入，先记录资源消耗，再决定是否建议降低质量或在后台生成工作副本。文件体积小不代表解码和重建内存占用小，不能承诺任意数量或分辨率都适合 16GB 内存。

实际测试需记录每组照片分辨率；计划纳入 24MP 实拍及条件允许时的 48MP 压力样本，不能只用已有 1080×1080 JPEG 或约 12MP 公共样例推断资源上限。具体配置与是否需要工作副本以实测结果确定。

## 10. 开发步骤与阶段验收

在已有工程和验证成果上按以下七个阶段增量推进。阶段 1–7 对应差异分析计划中的 S0–S6；历史验收记录里的阶段编号沿用 v1 定义，不据此重新认定功能完成状态。

第一批交付以阶段 1 和阶段 2 的最小增量为主：真实 HEIC/JPEG 结果、原图直入或工作副本策略、照片与运行快照结构、旧项目迁移和保护测试。后续依次完善导入、界面和 P0 实拍闭环，再接入完整 P1。

### 阶段 1：建立真实 HEIC/JPEG 基线

步骤：

1. 保留现有工程、上游许可、JPEG 基线与取消/失败验证记录；核实测试照片目录、来源、数量、分辨率、方向和颜色信息。
2. 分别使用 59 张 HEIC、33 张 JPG 建立读取、重建和 USDZ 导出基线；TMO 只选择 `rgb/`，不提供外部相机、深度或轨迹文件。
3. 优先测试原图直入。若失败，区分解码、引擎输入、资源压力和模型质量问题，只针对有证据的问题准备工作副本。
4. 在应用与独立查看器或渲染器中检查输出，确认网格、UV、材质及颜色贴图完整；记录耗时、资源占用和失败原因。
5. 尽早用 iPhone 16 Pro 系统相机原始 HEIC 验证实际入口；合格实拍组已就绪时同步完成真实重建。
6. 延续现有 P1 探针，小范围检查样本 ID 关联、坐标和投影，不在本阶段建设完整视角界面。

验收：至少一组真实 HEIC 和一组 JPEG 完成彩色贴图重建与导出，并有可复查记录；明确是否需要工作副本以及已测资源范围。HEIC 失败修复前不标记兼容通过；自拍照片尚未就绪时可继续后续开发，但首版实拍验收保持未完成。

### 阶段 2：完善数据结构和迁移

步骤：

1. 扩展照片记录，保存稳定 ID、实际类型、主图索引、内容摘要、尺寸方向及可用元数据。
2. 定义工作版本与每次重建的输入快照，记录来源、处理配方、坐标变换和文件关联；只实现基线验证确需的转换。
3. 扩展项目格式和旧版本读取/迁移，保留原照片 ID、原图与可用模型。
4. 建立模型、输入快照与后续相机结果的同一运行引用，按第 8 节实现原子提交和失败恢复。
5. 验证项目移动、清理缓存、重新打开和写入失败；确保必要映射不随临时文件丢失。

验收：已有项目无需重建即可打开；照片身份、处理记录和成功结果可恢复；迁移或提交失败不破坏原项目；删除缓存不影响已有模型及必要转换记录。

### 阶段 3：补齐导入能力

步骤：

1. 完善内容识别、HEIF 主图选择、方向、颜色及缩略图规则，后台逐张处理。
2. 支持跨批次和重开后的精确去重；同名不同内容不覆盖，照片 ID 不随排序改变。
3. 分类记录已导入、重复、不支持的照片、无法读取和已忽略；保留非递归文件夹导入行为。
4. 混合输入时继续处理有效照片；缺少 EXIF、深度或轨迹不单独构成拒绝理由。
5. 将逐张导入问题与引擎样本问题关联到可靠身份；不可读照片有文件名占位行，内部诊断不直接替代用户说明。

验收：HEIC/JPEG、DNG、MOV、辅助文件和损坏文件混合选择时，分类与计数准确，有效照片可继续使用；原图字节保留，重复处理可解释，无同名覆盖或排序错配。

### 阶段 4：简化界面并加入可恢复草稿

步骤：

1. 首次启动直接添加或拖入照片，自动建立可恢复草稿；保存时再选择正式名称与位置。
2. 导入后突出“开始重建”，使用经基线验证的推荐配置；质量和背景隔离等选项折叠显示。
3. 明确准备、重建、保存、完成、取消和失败状态；只有可靠引擎进度显示百分比。
4. 提供简洁摘要、逐张问题及可展开诊断，不猜测未经检测的模糊或覆盖问题。
5. 验证退出恢复、保存取消、目标不可写和迁移中断；保持已有模型查看、导出及输入变更后的过期提示。

验收：用户无需先选项目位置或质量即可添加照片并开始重建；草稿可恢复，保存失败保留资料，只有正式保存成功才切换项目位置。

### 阶段 5：完成 P0 实拍验收

步骤：

1. 在最终应用中，用 iPhone 16 Pro 系统相机 HEIC 原文件走通添加、重建、查看、保存、关闭重开和导出。
2. 验证普通 JPEG 无辅助资料路径，以及横竖方向、混合格式、重复文件和缺少元数据等输入。
3. 检查带贴图 USDZ 的独立渲染；记录应用查看与导出后的几何、材质和颜色表现。
4. 执行真实 UI 的取消、失败重试、草稿恢复、旧项目迁移、项目移动和保存失败验证；服务测试与 UI 验收分别记账。
5. 根据实际分辨率记录高分辨率照片及较大批次的资源消耗，完成第 11 节的 P0 必要项。

验收：用户不做第三方格式转换、不提供辅助文件、不输入相机参数即可完成上述闭环；旧项目无需重新重建。iPhone 16 Pro 原始 HEIC 未真实成功前，不标记 P0 全部通过；公开样例或重新编码的 HEIC 不替代该验收。

### 阶段 6：接入 P1 照片视角

步骤：

1. 在 P0 验收后接入完整功能；同一会话请求模型与 `.poses`，分别管理状态并持续监听至会话结束。
2. 保存照片 ID、工作版本、样本 ID、相机参数及模型的关联，记录定位状态和坐标约定。
3. 从正面、侧面和斜上方各选一张可定位照片，验证相机方向、内参、画幅和投影；不能只设置相机位置就认定构图正确。
4. 检查工作副本方向/尺寸、引擎降采样及畸变处理；采用经探针验证的投影路径，近似或参数不足的情况明确标记。
5. 实现点击照片切换视角、原图并排对比、固定画幅、自由观察及返回照片视角。
6. 用无外部轨迹的普通照片验证，覆盖保存重开、清缓存和工作副本路径；仅位姿失败时保留成功模型，不混用旧相机。

验收：照片映射准确，至少三个不同机位的观察方向与构图有可核对记录；原图与工作副本路径均可恢复；未定位、近似和位姿请求失败时行为明确。生成位姿 JSON 本身不代表照片视角通过。

### 阶段 7：稳定性与交付

步骤：

1. 用多个适用材质、较大批次和持续查看操作测试，记录质量边界、资源压力及失败案例。
2. 回归取消、重试、无效图片、草稿、项目移动、清缓存和保存失败的恢复行为。
3. 优化纹理加载、缩略图缓存与查看器响应；依据实测决定是否增加质量档位。
4. 完善使用说明、拍摄建议、支持范围、已知限制及可复现构建记录，保留上游许可。
5. 按交付范围验证签名、公证及其他机器运行，分别记录完成状态；本机 ad-hoc 构建通过不等于分发验收通过。

验收：关键流程可重复完成，模型颜色正确，项目数据可恢复，资源消耗和失败恢复有记录，交付包及说明与实际支持范围一致。

## 11. 验证方法

### 11.1 普通照片入口：首版必须通过

| 验证场景 | 通过条件 |
| --- | --- |
| iPhone 16 Pro 系统相机 HEIC 原文件 | 原样导入并完成彩色模型闭环，用户不做格式转换 |
| 普通 JPEG 照片，没有外部深度/轨迹文件 | 可仅凭照片启动并完成测试物体重建，不索要辅助文件 |
| 同组包含竖拍、横拍与方向标记 | 缩略图和原图显示正确，工作副本的方向与坐标记录一致 |
| 混合 HEIC / JPEG 与无关辅助文件 | 有效照片正常导入，其余文件有简短说明；不将其当作整体错误 |
| 暂不支持的 DNG 或伴随 MOV | 明确区分不支持的照片与忽略的视频，不阻止使用其他有效照片 |
| 重复文件、不同目录中的同名文件 | 重复处理可解释，不覆盖不同照片；照片 ID 不随排序改变 |
| 跨批次、重开项目后再次添加同一文件 | 精确去重结果可解释，不因重新启动而重复计数 |
| 缺少拍摄元数据但仍可解码的照片 | 不仅因缺少元数据而拒绝启动；记录实际重建结果和限制 |
| 保存项目后移动项目位置，再次打开 | 原图、模型、已有视角和必要变换关系可恢复 |
| 首次添加照片、退出后恢复草稿 | 无需先选项目位置；已落盘的原图、清单和成功结果可恢复 |
| 原图与工作副本 | 原图导入前后内容摘要一致；必要转换独立保存处理记录 |

首版通过标准不是“研究工程目录能够导入”，而是“用户只交给应用照片，也能完成规定测试对象的重建”。这不表示任意拍摄内容都能成功。

### 11.2 测试数据安排

| 测试组 | 已知内容 | 用途及现状 |
| --- | --- | --- |
| iPhone 16 Pro 自拍组 | 系统相机拍摄同一静止物体的 HEIC / JPEG；不附专门采集数据 | 最重要的产品验收数据，需用户实际采集并测试 |
| Kalenji 既有基线 | 155 张 1080×1080 JPEG | 已完成真实重建、应用内查看、保存重开、导出与独立 SceneKit 渲染；保留作回归，不替代 HEIC、高分辨率及实拍验收 |
| McNeel 鞋子样例 | 59 张 HEIC，4032×3024；文件元数据标记 iPhone 13；包含翻面拍摄 | 已在本机下载、检查并完成原图直入、彩色模型重建、导出及独立渲染；应用内草稿恢复、重建、保存、重开及导出均通过，见 v2 验收记录 |
| TMO AR-Capture / Shoe | 33 张 JPG，实际尺寸 3024×4032；作者注明 iPhone 13 Pro | 已只导入 `rgb/` 完成新版重建、输入快照保存、重开导出与独立彩色渲染；不使用外部轨迹、相机或深度数据 |
| PIX4D Olympic Flame | 117 张 JPG，1920×1440、方向 6，来源为 PIX4Dcatch；包内另有相机信息、点云和 OPF 工程 | 已仅用 `images/` 完成原图直入重建、独立彩色渲染及应用重开；细薄结构与动态火焰有质量限制，不计作系统相机实拍或高分辨率验收 |

不把 TMO 的轨迹当作精确测量真值；比较之前应统一坐标与尺度。公开样例的来源与许可应单独记录，未经核实不将第三方图片直接打包进入公开仓库。

阶段 1 应核实各组实际文件和元数据。自拍组尚未就绪时，可以继续公开样例、持久化、导入和界面工作；最终实拍验收保留为未完成，不以 JPEG 重新编码的 HEIC 代替 iPhone 原文件。

### 11.3 重建质量

- 使用静止、有纹理的物体，从不同高度拍摄，保证相邻照片有充分重叠。
- 在应用中从多个角度检查模型，同时查看带纹理和几何轮廓，避免仅凭贴图判断几何质量。
- 将导出的 USDZ 放入另一个支持的查看器，确认材质与颜色确实随文件保存。

### 11.4 视角恢复

- 检查照片与相机记录一一对应，没有错位或依赖偶然排序。
- 在若干照片上使用物体轮廓或明显表面特征做原图对比。
- 分别记录机位错误、画幅错误、畸变差异和几何缺陷，不用一个“对不上”掩盖不同原因。
- 如需要量化，可记录选定特征点的屏幕偏差；阈值应根据测试数据和用途确定，不在验证前承诺像素级精度。

### 11.5 项目可靠性

- 保存、关闭、重开后，模型、照片与已有视角均可恢复。
- 整个项目移动目录后仍能打开。
- 旧版本项目迁移后保留照片 ID 和可用模型；迁移写入失败时原项目仍可打开。
- 清除缓存后，已有模型、必要转换记录及 P1 相机资料仍可恢复。
- 草稿退出后可恢复；正式保存取消、失败或中断时保留原资料，不提前清理草稿。
- 重建取消或失败，不损坏已有成功结果。
- 模型成功但位姿请求失败时，保留新模型并标明视角不可用，不绑定旧模型的相机记录。
- 测试图片读取失败、内存压力和输出写入失败时的提示与恢复行为。

自动化测试优先覆盖照片 ID 映射、精确去重、方向与工作副本坐标转换、矩阵与投影转换、项目迁移和原子提交、草稿恢复及任务状态处理。重建质量与纹理效果使用真实样本验证，不能只靠模拟数据测试代替；服务验证与完整 UI 流程分别记录。

## 12. 暂不纳入首版

- 云端账号、上传服务和付费系统。
- 自行训练三维重建模型。
- 通用研究数据集解析器、手动相机标定界面、要求用户制作深度或轨迹的导入流程。
- 将专用 iPhone 扫描应用作为使用前提。
- 对 Apple ProRAW / DNG、所有 Live Photo 资产类型和任意视频直接重建的支持承诺。
- 同时开发 Windows、Android 和 Web 重建端。
- 医疗级、工业测量级精度承诺。
- 任意物体、任意照片都能成功的承诺。
- 高斯泼溅作为主要模型输出。
- 自动补全不可见表面并将其视为实测结果。

这些方向可以后续讨论，但不应拖延本地带贴图三维重建功能的完成。
