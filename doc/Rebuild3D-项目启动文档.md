# Rebuild3D 项目启动文档

> 项目定位：通过原生 macOS 应用，将多角度照片重建为带颜色贴图的三维模型。
>
> 拟用仓库名：`rebuild3d`
>
> 文档日期：2026-10-08
>
> 当前状态：P0 第一版已可编译、打包，13 项自动化测试通过；公开真实照片集已完成重建、带纹理查看、保存重开、USDZ 导出与独立渲染，真实取消/失败/重试保护已验证。完整 UI 流程、Xcode、实拍数据及 P1 仍有待办，阶段 0 / 1 尚未标记全部通过。详见 [本次验收记录](验收记录-2026-10-08.md)。

## 1. 项目主旨

Rebuild3D 是一个面向个人使用、可继续扩展的本地三维重建应用。用户打开应用后，导入同一物体的多角度照片，启动重建，得到可以旋转查看、保存和导出的带颜色贴图的三维模型。

**三维重建是项目的基础目标。** 产品名称、首页、开发顺序和验收标准都应围绕这一目标展开。

恢复原始照片的拍摄视角是重建完成后的查看与检查功能：用户选择某张照片，三维视窗切换到估计的对应机位，并允许对照原图查看模型。它不应取代三维重建成为产品的主要定位。

GitHub 项目简介：

> A native macOS app for reconstructing textured 3D models from photographs.

## 2. 使用条件与初始范围

### 2.1 现有设备

- 开发与重建设备：MacBook Air M5，16GB 统一内存。
- 拍摄设备：iPhone 16 Pro。
- 首版采用本地处理，照片无需上传服务器。
- 首版可以使用 iPhone 系统相机拍照，再将照片传入 Mac；不依赖先开发一个 iPhone 应用。

### 2.2 首先支持的对象

优先支持静止、刚性、表面有可识别纹理的日常物体，例如鞋子、石雕、木制品和摆件。

“通用重建”表示不绑定人脸这一种对象。首版仍应从单个物体开始验证，不承诺所有材质、尺寸和场景都能成功重建。

玻璃、镜面金属、纯色光滑表面、细线结构和会移动或变形的对象属于困难场景。真人脸部、完整头部、房间和大场景可作为后续方向单独评估。

### 2.3 对三维结果的定义

合格结果至少包含：

1. 三角网格：表达物体表面形状。
2. UV 坐标及颜色贴图：将照片中的表面颜色映射到网格。
3. 可用材质：让模型在支持的查看器中正常显示颜色。

仅得到灰色网格、彩色点云或高斯泼溅数据，不满足本项目首版的完整输出要求。

首版主要输出格式为 **USDZ**。GLB、OBJ 等格式转换作为后续扩展，必须验证转换后贴图和材质仍然正确。只导出几何、不保留颜色的结果不能算转换成功。

## 3. 技术路线与上游项目

基于以下项目进行二次开发：

- 上游仓库：[ekarad1um/Photogrammetry](https://github.com/ekarad1um/Photogrammetry)
- 本次检查版本：`43c66741e3f912ddd29292858d6f6bc01441606e`
- 应用框架：Swift、SwiftUI、RealityKit。
- 重建引擎：Apple Object Capture / `PhotogrammetrySession`。
- 上游许可证：MIT；沿用代码时保留原有版权与许可声明。

上游应用代码开源，Apple 的底层重建引擎属于系统框架，并非本项目能够修改的开源算法。首版接受这一依赖，以完成苹果设备上的实际重建功能为优先。

上游规模较小，本次检查约为 16 个 Swift 文件、906 行代码，已有图片文件夹导入、参数设置、重建进度、简单模型预览和 USDZ 导出。可以复用这些基础，同时逐步拆分业务逻辑和界面。

建议新项目面向 **macOS 26 或更新版本**。理由是原始照片视角对齐需要的估计相机内参和镜头畸变接口从 macOS 26 起提供。基础相机位姿接口从 macOS 14 起可用；应用运行时仍须检查硬件与 API 支持情况。

开发开始前核实本机 macOS、Xcode、SDK 版本，并先验证上游项目是否能够编译和完成一次重建。

## 4. 目标使用流程

1. 打开 Rebuild3D，新建项目或打开已有项目。
2. 拖入图片文件夹或选择多张照片。
3. 查看照片缩略图、数量及格式问题，移除不需要的照片。
4. 选择重建质量，点击“开始重建”。
5. 查看进度；必要时取消，失败时看到可理解的原因。
6. 重建完成后，在主视窗中查看带颜色贴图的三维模型。
7. 自由旋转、缩放和移动视图，检查模型各个角度。
8. 在后续视角功能中，点击原始照片，将三维相机切换到对应估计机位，并对照原图。
9. 保存项目；关闭应用后再次打开，直接恢复模型和已有结果。
10. 根据需要导出 USDZ 模型。

保存项目与导出模型是不同操作：保存项目保留后续查看所需的照片、参数和相机信息；导出模型生成交给其他软件使用的三维资产。

## 5. 功能优先级

### P0：基础三维重建闭环

- 新建、保存和打开本地项目。
- 导入图片文件夹及多张照片，展示缩略图。
- 对明显无效、无法读取或不支持的输入给出提示。
- 调用 Object Capture 生成带颜色贴图的模型。
- 显示重建进度，支持取消与失败后重试。
- 在应用中查看模型，支持自由旋转、缩放、平移及重置视图。
- 导出包含贴图的 USDZ。
- 关闭并重新打开项目后，可以直接查看已完成模型。

### P1：原始照片视角与对比

- 获取并保存参与重建照片的估计相机位置和朝向。
- 建立照片、样本 ID 和相机参数之间的稳定映射。
- 点击照片切换三维相机，恢复对应的观察方向与尽可能一致的构图。
- 显示原图与三维渲染的并排对比。
- 标明“已定位”“未定位”“近似视角”等状态。
- 支持切回自由观察模式；保存并重开项目后，照片视角仍然可用。

P1 应尽早做一个小范围技术验证，以检查坐标与投影是否正确；其完整界面和高级对比功能不应阻塞 P0 交付。

### P2：后续增强

- 原图与渲染画面的半透明叠加、分割线对比。
- 在三维空间显示拍摄机位或视锥。
- GLB、OBJ 等模型格式转换。
- 更完整的质量诊断、批量重建与性能优化。
- iPhone 引导扫描端及深度信息采集。
- 对人脸、室内空间等特定对象建立单独的采集与重建策略。

## 6. 界面方案

采用可调整大小的 macOS 主窗口，替换上游固定尺寸的步骤式小窗口。

| 区域 | 内容 |
| --- | --- |
| 顶部工具栏 | 新建、打开、导入照片、开始重建、取消、保存、导出 |
| 左侧照片栏 | 缩略图、照片名称、选择状态；P1 增加定位状态 |
| 中间主视窗 | 带贴图的三维模型；未重建时显示简明引导；重建时显示进度 |
| 可展开的右侧面板 | 原图、重建设置、错误说明；P1 增加视角对比 |
| 底部状态栏 | 项目状态、照片数量、重建进度与必要提示 |

交互约定：

- “开始重建”应是导入照片后的主要操作。
- 点击照片后，高亮当前照片；有位姿时进入照片视角，没有位姿时显示原因并保留原图查看。
- “照片视角”保持原照片画幅；窗口大小变化时使用留边等方式，避免改变构图。
- 自由拖动三维视图后进入“自由观察”，用户可点击“返回照片视角”。
- 重建错误应说明发生了什么、哪些输入受影响、是否可以重试，避免只显示内部错误码。

## 7. 重建与视角恢复的实现要点

### 7.1 重建服务

将重建逻辑封装为独立服务，管理输入、配置、进度、取消、输出和错误。界面只观察状态和发出操作，不直接承担全部重建流程。

第一版沿用 `PhotogrammetrySession` 的模型输出。接入 P1 时，在同一会话中请求模型和 `.poses`，分别记录每一类请求的完成、失败和进度。

**不能在第一个请求完成时就退出结果监听。** 上游当前的结果处理有这一行为；加入 `.poses` 后，需要修改为收集所需结果，并按整体会话状态结束。模型已成功、位姿失败时，应保留可用模型并单独提示视角功能不可用。

### 7.2 照片与相机的对应

- `posesBySample` 提供样本 ID 到估计相机位姿的映射。
- 使用图片文件夹创建会话时，可利用 `urlsBySample` 对应原始图片。
- 使用自定义样本序列时，由应用维护样本 ID 到图片的映射。
- 不根据文件夹枚举顺序或文件名排序猜测位姿对应关系。
- 被跳过、无效或未成功定位的照片要保留明确状态，不能伪造视角。

### 7.3 恢复观察方向与构图

视角恢复需要同时处理：

1. 相机位置与朝向。
2. 相机内参，包括焦距与主点。
3. 图片尺寸、方向信息、裁剪和显示宽高比。
4. 可用的镜头畸变信息。
5. 重建模型、导出模型和查看器之间的坐标变换。

Apple 的内参和畸变数据可能为空。存在这些参数时按参数构建投影与对比流程；缺失时可用可验证的近似方案，但必须在界面和保存数据中标记。仅设置相机位置和朝向不足以承诺与原照片构图一致。

原图叠加时，原图和渲染画面应处于同一种投影条件下。例如使用已校正的原图对比针孔相机渲染，避免把镜头畸变误认为重建几何误差。

### 7.4 坐标处理

上游预览会将模型平移到中心，使用固定 80° 视场角，再自动环绕展示。这一逻辑需要改造。

保持重建模型与相机参数的坐标关系。若为方便显示而对模型施加平移、旋转或缩放，相机和其他辅助对象必须应用一致的坐标变换。

开发中明确记录矩阵方向、坐标轴约定、单位和矩阵存储顺序，避免相机朝反方向、模型镜像或投影比例错误。不要在没有验证的情况下直接把外参矩阵赋给查看器相机。

### 7.5 效果边界

恢复的是算法估计的机位，不能保证所有输入照片都有位姿，也不能保证渲染结果和原图逐像素相同。

原图包含背景、现场光照、反光和遮挡；重建模型存在缺失、平滑和纹理融合。这些因素都会产生差异。没有深度或已知尺度约束时，也不能将重建结果直接作为准确的尺寸测量工具。

## 8. 项目文件与持久化

不能只保存一个模型文件，也不能将唯一结果留在临时目录。

建议使用自包含的项目目录或 macOS 文档包。以下是拟议结构，具体扩展名在实现时确定：

```text
Example.rebuild3d/
  project.json       # 版本、项目设置、输入清单、结果和状态
  images/            # 原始输入照片，保留可用元数据
  thumbnails/        # 照片列表缩略图，可重新生成
  models/
    model.usdz       # 包含材质和贴图的重建结果
  cameras.json       # P1：样本、位姿、内参和照片映射
  logs/              # 任务日志与失败原因
  cache/             # 可清理的中间数据
```

保存约定：

- 原图默认复制到项目内，避免外部照片移动或删除后项目失效。
- 项目内使用相对路径，允许整个项目目录移动。
- 元数据包含格式版本，便于以后迁移。
- 相机记录包含样本 ID、照片路径、位姿、可用内参、图片尺寸与方向、定位状态，以及使用的坐标约定。
- 保存尽可能采用原子写入；界面显示是否还有未保存内容。
- 已有可用模型在新一轮重建失败时仍应保留。
- 区分可删除缓存和不可丢失的项目资料。
- 保存并重开项目不要求重新重建；中断后的重建断点续算属于另一个功能，首版不承诺。

上游当前会在离开预览页面时删除临时模型。二次开发时必须移除这种结果生命周期设计，改为由项目管理层负责保存和清理。

## 9. 16GB 内存下的资源策略

- 一次只运行一个重建任务。
- 首先使用 `reduced` 或 `medium` 质量进行验证。
- 照片列表使用缩略图，原图按需读取。
- 避免同时将全部原图、所有纹理和重复模型常驻内存。
- 输入处理、重建和保存避免阻塞主界面。
- 缩放或转换照片时保留原图，正确更新与像素尺寸相关的相机参数。
- 记录任务耗时、内存峰值、输出大小和失败原因，再决定是否增加更高质量档位。

可先用约 80–150 张、约 1200 万像素的照片建立测试集。这是初始试验配置，不是硬件上限、必需照片数量或性能保证。

## 10. 开发步骤与阶段验收

### 阶段 0：建立工程与重建基线

步骤：

1. 创建 Rebuild3D 仓库，导入或派生上游代码。
2. 保留 MIT 许可与原作者声明，在 README 记录上游来源和起始提交。
3. 修改应用名称、标识和工程配置，核实 macOS 与 Xcode 环境。
4. 编译运行现有应用，使用一组稳定照片完成重建和 USDZ 导出。
5. 记录基线结果、耗时和资源占用。

验收：应用可以启动，能够生成并打开有颜色贴图的模型；失败时有可追踪记录。

### 阶段 1：完成 P0 三维重建应用

步骤：

1. 建立项目数据模型与本地保存结构。
2. 重构照片导入，支持文件夹、多文件和缩略图。
3. 封装重建服务及任务状态。
4. 将固定小窗口改为可调整的主界面。
5. 完成带贴图模型的自由查看与 USDZ 导出。
6. 完成项目保存、打开及已有结果恢复。

验收：导入照片、重建、查看、保存、重开和导出的流程完整可用。打开旧项目不必重新重建。

### 阶段 2：验证并接入原始照片视角

步骤：

1. 在重建会话中增加 `.poses` 请求，修正多请求结果处理。
2. 保存照片与相机位姿的映射，验证样本没有对应错误。
3. 从正面、侧面和斜上方各选一张可定位照片，验证相机朝向和坐标。
4. 接入可用内参、图片方向和画幅处理，检查构图。
5. 实现点击照片切换视角与原图并排对比。
6. 保存相机数据，并验证关闭、重开后结果一致。

验收：点击已定位照片能够切换到对应估计视角；原图和模型具有合理一致的观察方向与构图；未定位或参数不足的情况有明确状态。

### 阶段 3：质量、稳定性与交付

步骤：

1. 用多个不同材质的物体测试，记录适用条件与失败案例。
2. 检查取消、失败重试、无效图片、项目移动和保存失败等情况。
3. 优化纹理加载、缩略图缓存及查看器响应。
4. 完善使用说明、拍摄建议和已知限制。
5. 构建可分发应用，记录签名及运行要求。

验收：关键流程可重复完成，模型颜色正确，项目数据可恢复，资源消耗有实际记录。

## 11. 验证方法

### 重建质量

- 使用静止、有纹理的物体，从不同高度拍摄，保证相邻照片有充分重叠。
- 在应用中从多个角度检查模型，同时查看带纹理和几何轮廓，避免仅凭贴图判断几何质量。
- 将导出的 USDZ 放入另一个支持的查看器，确认材质与颜色确实随文件保存。

### 视角恢复

- 检查照片与相机记录一一对应，没有错位或依赖偶然排序。
- 在若干照片上使用物体轮廓或明显表面特征做原图对比。
- 分别记录机位错误、画幅错误、畸变差异和几何缺陷，不用一个“对不上”掩盖不同原因。
- 如需要量化，可记录选定特征点的屏幕偏差；阈值应根据测试数据和用途确定，不在验证前承诺像素级精度。

### 项目可靠性

- 保存、关闭、重开后，模型、照片与已有视角均可恢复。
- 整个项目移动目录后仍能打开。
- 重建取消或失败，不损坏已有成功结果。
- 测试图片读取失败、内存压力和输出写入失败时的提示与恢复行为。

自动化测试优先覆盖照片 ID 映射、矩阵与投影转换、项目序列化和任务状态处理。重建质量与纹理效果使用真实样本验证，不能只靠模拟数据测试代替。

## 12. 暂不纳入首版

- 云端账号、上传服务和付费系统。
- 自行训练三维重建模型。
- 同时开发 Windows、Android 和 Web 重建端。
- 医疗级、工业测量级精度承诺。
- 任意物体、任意照片都能成功的承诺。
- 高斯泼溅作为主要模型输出。
- 自动补全不可见表面并将其视为实测结果。

这些方向可以后续讨论，但不应拖延本地带贴图三维重建功能的完成。

## 13. 项目启动时的首个开发任务

> 基于 ekarad1um/Photogrammetry 建立 Rebuild3D 原生 macOS 工程，以本地带颜色贴图的三维重建为首要目标。先验证上游编译和一次真实照片重建，再完成照片导入、模型查看、项目保存与重开、USDZ 导出的基础闭环。保留上游许可与来源，按 16GB 内存设备设计资源使用。随后接入相机位姿和可用内参，实现点击原图恢复估计拍摄视角。不要把视角恢复做成产品主旨，也不要在基础重建未验证前扩展到云服务或其他平台。
