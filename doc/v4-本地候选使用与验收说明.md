## 怎样使用

当前工作区的应用在 `build/v4-quantization/delivery/Rebuild3D-v4-candidate-10.app`。在 Finder 中打开它，添加同一物体的照片，然后点击生成即可。首次使用需要准备本机组件，后续会自动复用并检查完整性；用户不用选择量化位宽、计算引擎或执行脚本。

需要搬到其他目录时，可解压本地 `build/v4-quantization/archive-candidate-10/Rebuild3D-v4-candidate-10.zip`，再打开其中的应用。该 ZIP 已实际解压到含中文和空格的路径，并完成签名、依赖和离线应用检查；没有上传到 GitHub Release。

生成完成后，先旋转检查模型，再保存项目。保存项目可以保留照片、结果及来源信息，便于重开与继续工作；导出用于在其他软件中查看模型。USDZ 内嵌贴图，随导出的结果附件还包含 GLB 与来源资料，建议一并保留。候选导出的 A/B 模型已在系统 Preview 中移位打开并显示贴图。

生成过程可以取消。实际测试中，在推理时取消、退出应用、重新打开项目并再次生成后，程序保留旧模型，复用有效的照片准备结果，再生成新模型。失败或换图后的旧结果不能当作本次生成成功。

界面中的“颜色来源”可以查看不同照片的贡献和外观填充区域。照片取色也不意味着对应形状经过实测；未拍到部分的形状和颜色仍有推测。

## 与 v3 相比做了什么

| 改动 | 已核实的情况 |
| --- | --- |
| 量化模型 | 主干采用 MLX W8、group 32；约 78.24% 的启用参数进入真实低位计算，输出头保留较高精度。并非所有数据与运算都是 8 位 |
| 权重与应用体积 | 权重约 1.523 GB，展开应用约 2.940 GB，ZIP 约 1.844 GB；均为十进制单位 |
| UV 处理 | 自动分块展开，修复图块重叠与狭长三角形的采样问题；仍从原照片重新制作约 4K 贴图 |
| 几何与显示 | 修正相关面朝向、导出法线及锐边平滑问题；已复查正常尺寸和降低尺寸后的指定成品 |
| 推理调度 | 候选 10 改为异步提交各层计算，在主干返回前等待 GPU 完成；不改变权重、精度、照片数量或输出预算 |
| 资源不足重试 | 真实受控分配失败已触发 518 → 392 的一次重试并生成结果；这不等于已在 8 GiB Mac 上完成验收 |
| 离线与恢复 | 已通过实际应用断网导入、生成、显示、保存重开、导出，以及取消后退出重启续跑 |

应用首次准备会另保留一套运行组件。候选应用与一套准备完成组件的逻辑总占用约 **5.869 GB**，还不含照片和项目；ZIP 大小不是安装后的总占用。旧版组件会保留以保护兼容性，升级时需要相应磁盘空间。APFS 实际独占物理占用未测。

## 现在能保证到什么程度

本机为 Apple M5、16 GiB 内存、macOS 26.4.1。候选 10 已在两套用户七图上实际生成带贴图模型，两组移位 USDZ 也已在系统 Preview 中显示贴图。候选 09 完成的 3–12 张、倒序、中文/空格路径、EXIF 1–8 方向及 HEIC 变体检查保留原版本范围；候选 10 又检查了受影响的推理输出，包括 3–12 张、倒序与 392 输入，并核对未改变的应用及原生组件。这些是已测输入的结果，不保证任意照片都能精确重建。

少图结果仍可能存在孔洞、薄杆缺失、顶部切口、扁平或台阶状表面、底部额外薄片、接缝和粗糙补全色块。对照审核通过表示已审范围符合相应的相对质量要求，不代表与真实物体完全一致。照片数量更少、角度覆盖不足时尤其明显。

**尚不能宣称 v4 全部性能与资源目标达标。以下数字属于候选 09。** A/B 各三轮原版与候选 09 的 12 次实际应用交错测试已完成：完整推理中位耗时分别减少 **18.87% / 18.36%**，尚未达到 20%；推理物理峰值约降低 **27%**。实际点击到模型可见的中位数区间，A 从约 **279–301 秒**降到 **83–89 秒**，B 从约 **106–115 秒**降到 **64–74 秒**。这些区间保留窗口观察的不确定性；后台负载变化及 A 组 swap 增量仍需控制条件后复验，不能将这批数值直接视为全部资源验收通过。证据见 `build/v4-quantization/ui-performance-01/summary-after-12.json` 与 `environment-review-01/report.json`。独立新对象 E2 的完整相对质量对照已通过，仍保留双方共有的底部形变和贴图接缝。

候选 10 的正式对照在 `ui-performance-02/`，A/B 各三轮共十二次均生成并实际显示带贴图模型。完整推理中位耗时降幅 A/B 为 **19.43%/20.64%**，A 未达到 20%；推理进程树物理峰值均降低约 26%，实际等待保守降幅为 **60.13%/30.71%**。A 点击到确认显示窗口的整机 swap 增量中位数从约 492 MB 增至 627 MB，因此资源与环境条件也未通过。第 4 份观察延迟及第 9 份锁屏保留计时上下界，不能把上界当成精确生成耗时；整机 swap 也不能全部归因于重建。最终判定见 `environment-review-01/review-decision.json`，下一步优化启动与加载后复验。

独立离线 GUI 测试使用已准备的组件；空组件目录的断网准备另有核心代码测试，两者的证据范围不同。候选 10 的对应记录为 `offline-ui-03/` 和 `offline-core-03/`。取消后正常退出重启已有实测，生产核心还验证了推理子进程异常恢复；不能扩大成所有崩溃或所有故障均已覆盖。
