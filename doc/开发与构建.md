# Rebuild3D 开发与构建

本文面向从源码构建 v0.1.0 的开发者。完整应用运行在本机，不需要用户在生成时执行下面的命令。当前发布源码及截图；验收用原图、模型、权重和完整运行环境不在 Git 仓库中。

## 1. 原生目标

验证环境为 Apple M5、16 GiB、macOS 26.4.1、Swift 6.3.1 和 macOS 26.4 SDK。需要支持 Object Capture 的 Mac；目前只验证 arm64。

```sh
swift build
./scripts/test.sh
swift run rebuild3d-check doctor
```

`scripts/test.sh` 为仅安装 Command Line Tools 的环境补充 Swift Testing 搜索路径。普通原生开发包可用 `./scripts/build-app.sh release` 构建，但它不包含少图运行组件；完整流程使用下文的 `scripts/v3/build-app.sh`。

## 2. 准备固定版本组件

打包工具读取**已有、已验证**的开发组件。准备以下内容，放在被 Git 忽略的 `build/` 内或其他工作目录中：

| 组件 | 固定版本或要求 |
| --- | --- |
| Python | 可迁移的 standalone CPython 3.12；本机验收为 3.12.13。虚拟环境的 `sys.base_prefix` 中必须含 `bin/python3.12` |
| Python 依赖 | 按 [`scripts/texture/requirements-macos.lock`](../scripts/texture/requirements-macos.lock) 安装到该 Python 的虚拟环境 |
| VGGT 代码 | [`facebookresearch/vggt`](https://github.com/facebookresearch/vggt)，提交 `a288dd0f14786c93483e45524328726ab7b1b4ce` |
| VGGT-1B 权重 | [`facebook/VGGT-1B`](https://huggingface.co/facebook/VGGT-1B/tree/860abec7937da0a4c03c41d3c269c366e82abdf9)，revision `860abec7937da0a4c03c41d3c269c366e82abdf9` 的 `model.safetensors` |
| 权重 SHA-256 | `f164acf60724910d8fe1578bb499d800850c7bb0948db7555c413f9fbe60467e` |

代码和权重适用不同许可，使用前阅读其原始许可。不要把其他 checkpoint 重命名后冒充已验证版本。Python 依赖包括本机平台的原生库，换平台后需要重新验证，不能直接照搬 arm64 环境。

以已经准备好的 standalone Python 为例创建开发环境；下列 `/absolute/path/...` 均需替换为本机实际位置：

```sh
/absolute/path/to/standalone/python3.12 -m venv build/runtime-venv
build/runtime-venv/bin/python -m pip install -r scripts/texture/requirements-macos.lock
git clone https://github.com/facebookresearch/vggt.git build/vggt
git -C build/vggt checkout a288dd0f14786c93483e45524328726ab7b1b4ce
```

从上表固定 revision 取得权重后，先核对摘要：

```sh
shasum -a 256 /absolute/path/to/model.safetensors
```

## 3. 构建完整应用

打包脚本会复制 standalone Python、虚拟环境依赖、固定 VGGT 源码与权重，构建本地光栅库，并登记每个文件的摘要。组件目录和应用输出路径都必须是新路径，不会覆盖已有安装组件或验收结果。

```sh
swift build --product rebuild3d-native-worker --configuration release
native_bin_dir="$(swift build --show-bin-path --configuration release)"

python3 scripts/v3/package-runtime.py build/runtime-v0.1.0 \
  --python build/runtime-venv/bin/python \
  --vggt build/vggt \
  --weights /absolute/path/to/model.safetensors \
  --native "$native_bin_dir/rebuild3d-native-worker"

bash scripts/v3/build-app.sh \
  build/runtime-v0.1.0 \
  build/release-v0.1.0/Rebuild3D.app

open build/release-v0.1.0/Rebuild3D.app
```

发布版本统一来自 `Config/Info.plist`（v0.1.0 / build 1），不从内部方案名 v3 推导。生成组件约 6.22 GB，首次生成还会复制到应用管理目录，另需为原图、检查点、模型和贴图预留空间。

应用内组件目录为 `~/Library/Application Support/org.rebuild3d.app/Runtimes/`，以组件摘要分版本管理。完整应用从包内准备和修复组件；当前没有在线组件下载器。

## 4. 运行时测试

Swift 测试使用上面的 `./scripts/test.sh`。Python 测试需要已打包的光栅库和依赖：

```sh
REBUILD3D_RASTER_LIBRARY="$PWD/build/runtime-v0.1.0/worker/rebuild3d_worker/raster.dylib" \
  PYTHONPATH="$PWD/Runtime" \
  build/runtime-v0.1.0/python/bin/python3.12 -m unittest discover \
  -s Runtime/tests -v
```

通过自动测试不代表重建质量通过。实际验收还包括完整应用生成、全部输入视角、固定细节、无纹理转台、来源查看、保存重开和移位导出，见[执行与验收记录](v3-一键生成执行与验收记录.md)。

`scripts/v3/probe-runtime.py` 只探测迁移后的依赖及 Metal 支持，不可单独用作完整应用的隔离环境验收结论。真实磁盘满测试使用独立小容量卷，不能填满工作盘。

## 5. 数据和历史实现

- `.rebuild3d` 项目格式为 3；格式 1/2 打开时保留原数据，成功保存后才原子迁移。
- 草稿位于 `~/Library/Application Support/org.rebuild3d.app/Drafts/`；`generation/` 中保存阶段检查点。
- 当前运行实现为 `Runtime/rebuild3d_worker/`；`scripts/sparse/` 与 `scripts/texture/` 保留前两阶段的研究复现，不是普通生成入口。
- `rebuild3d-check reconstruct/rebuild/export` 面向常规 Object Capture 检查，不等于完整应用的自动少图路线。
- 历史标签 `v0.2.0-sparse-baseline` 保留原指向；它是实验基线标签，本次首次正式 GitHub Release 使用 `v0.1.0`。

本机 ad-hoc 签名不等同于 Developer ID 签名或 Apple 公证。跨机器分发、商业授权和安装体验需要独立验证，不在本次源码发布的完成声明内。
