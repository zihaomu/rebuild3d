## S1：真正的 UV 与照片取样

先在冠饰/面部的 5219 个原面上做单图试验，实际 USDZ 渲染显示旧版丢失的浮雕、眼睛、胡须和嘴部细节。随后扩展到全部 488824 面。

使用 `xatlas==0.0.11` 的[非官方 Python 绑定](https://github.com/mworchel/xatlas-python/tree/v0.0.11)，绑定发行提交 `24d7e3e99e498eb11a94f5efd54fd9f754f2b88a`，该发行指向 [xatlas 提交](https://github.com/jpcy/xatlas/tree/f700c7790aaa030e794b52ba7791a05c085faf0c) `f700c7790aaa030e794b52ba7791a05c085faf0c`。两者许可、安装二进制摘要及依赖锁定保存在 `scripts/texture/`。安装的是 PyPI 发行二进制，核验了发行源码引用；未声称独立从源码重建并验证 wheel。

首次后处理遇到 NumPy 二维 `cross` API 差异，改用显式二维行列式。随后发现 525 个退化 UV 面，为每面单独分配带间隔的小岛。失败输出保留，没有覆盖最佳候选。最终全部 UV 面面积大于零，允许接缝复制顶点，但原三维角点、面顺序和推测分类精确不变。

原生展开实际 3228×3254；分别调整布局的像素预算为 2032×2048 和 4063×4096，再重新从照片烘焙。**没有把旧颜色纹理直接放大当成 4K。**

`bake.py` 在 atlas 像素中心反算原始面上的重心坐标，然后投影到完整 PNG，双线性取色。先用完整网格光栅化检查最近深度、朝向、主体 mask 和照片边界，面中心及实际 texel 都检查完整 mask。深度可见性工作图为 1200×1600，完整 mask 为 4284×5712；并非所有可见性计算都以原图分辨率运行。

## S2：投影、空隙与主体边界

逐张查看了七图的完整 mask、21 个原尺寸边缘裁片，以及衣带、手臂、器物和岩石间隙。继承的高分辨率 Vision mask 仍会封闭背景空隙，包含屋顶、招牌、树木或底部方台，不能因分辨率高就当成精确边界。

修订配置固定为 `mask-corrections.json`：手工多边形排除可确认的背景空隙；只在这些排除区周围增加 6 个工作像素的不确定带；下边界增加 8 个工作像素保守带，IMG_4527/4528 为 16。器物头部六张照片的已知小框内排除明显蓝天并留 3 个原图像素余量，没有全图按蓝色抠除，避免误删真实铜绿。IMG_4528 的器物头部被遮挡，不使用这项小框规则。

r6 在实际视角 3 渲染中消除了此前器物孔隙的明显蓝天污染。边界不确定处采用有标记的低频填充，没有删除网格面或将器物整体腐蚀掉。mask 仍是保守估计；记录在 `inputs-mask-r6/`，摘要决定具体版本。`maskRevision: 3` 是该修订算法的系列字段，不能代替不同实验 mask 的 SHA-256。

相机检查采用主体 mask 内的双向 SIFT 比率匹配、基础矩阵 RANSAC、网格可见性和空间保留点划分。`projection-audit-r2/report.json` 的初始误差（1200×1600 像素）如下：
